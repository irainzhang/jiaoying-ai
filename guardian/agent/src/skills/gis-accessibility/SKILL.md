# 路网与应急可达性

## 适用场景

- 用户问「这个社区到最近的安置点要多少分钟」「哪条路断了影响哪些片区」。
- 用户问「现在的车、床位、无障碍位够不够」「缺口在哪个方向」。
- 调度方案生成前判断哪些网格是可达的、哪些是结构性缺口。
- 复核调度方案是否用到了已阻断路段。

## 输入与前置条件

- 依赖演练路网快照（节点、边、通行时间）与当前道路开放/阻断状态。
- 依赖避难点、医院等演练设定 POI 及其容量字段。
- 仅使用**开放路段**参与计算。已阻断、已封闭路段必须排除在路径之外。
- 路网与 POI 均为合成演练设定，不代表真实道路与真实设施。

## 执行步骤

1. 读取当前路网状态，确认哪些路段被标记为阻断或封闭。
2. 调用 `analyze_accessibility`，以 **Dijkstra 最短路**在开放路段上计算各网格到
   避难点、医院的最短通行时间（分钟）。
3. 检查返回结果中的不可达集合：**任何因路网阻断而无法到达的网格，必须作为缺口显式报告**，
   不得从统计中静默剔除、也不得用默认值顶替。
4. 调用 `analyze_resource_gap`，对照需求（待转移人数、需无障碍协助人数）
   与现有能力（安置容量、无障碍位、车辆座位、车辆数）算出差额。
5. 将缺口按类型分组：容量缺口、无障碍位缺口、运力缺口、可达性缺口（含不可达网格）。
6. 对每个缺口说明成因：是资源总量不足，还是资源存在但被阻断路段隔开。
7. 输出中给出部分覆盖情况：已覆盖网格、覆盖不足网格、完全不可达网格。
8. 结束前附带下一步动作按钮（生成调度方案、按新变化重新研判、查看当前状态）。

## 输出要求

- 可达时间以分钟为单位，注明是演练路网上的最短路通行时间。
- 缺口用「现有 / 需求 / 差额」三元组表达，不要只说「缺口较大」。
- 不可达网格单独成列，写清是因为哪一类阻断导致，并标注为**未解决缺口**。
- 地图展示说明须遵守中国地图规范使用要求：使用合规底图与合规数据来源。
- **本演示不加载任何在线底图**，界面上的地图为原生绘制的演练示意图，
  必须在展示或描述地图时说明这一点，不得暗示其为在线地图服务或真实地理底图。
- 对可达性结论附一句边界提示：路网为演练设定快照，真实通行时间受现场管制、积水、拥堵影响。

## 禁止与边界

- 不得把不可达网格悄悄丢掉后宣称「全部覆盖」。
- 不得声称可达时间是实测数据或导航级路径规划结果。
- 不得使用或建议使用未经审阅的在线底图、境外地图服务或不符合地图管理要求的图源。
- 不得把演练路网描述为真实路网，也不得对真实道路的通行能力作断言。
- 不得在道路状态未知时假定道路畅通；状态缺失应作为数据缺口报告。
- 不得省略「演练设定、需人工确认」的边界声明。
