# 情景推演

## 适用场景

- 用户要求对比不同降雨强度下的风险与调度结果。
- 需要在决策报告中给出「雨情升级—需求升级」的对应关系。
- 研判当前方案在某些雨情档位下是否仍然成立。
- 演示与讲解时说明方案的弹性边界。

## 输入与前置条件

- 必须在**同一输入快照**上重算：同一路网状态、同一资源台账、同一人口结构、同一险情集合。
  仅改变累计雨量这一个变量，其余保持不变，否则对比不成立。
- 默认档位为累计雨量 **80 mm / 120 mm / 160 mm**，时程为 **6 小时**。
- 全部为演练设定与公开数据，不是预报产品。

## 执行步骤

1. 固定当前输入快照，记录快照时间，供三档共用。
2. 调用 `simulate_rainfall_scenario`，传入三档累计雨量（80、120、160 mm）与 6 小时时程。
3. 对每一档提取并列出：
   - 风险：各档风险等级分布，高与极高网格数量及其相对变化；
   - 暴露人口：受影响人口总数；
   - 脆弱人口：其中老龄人口、儿童、需协助人员数量；
   - 资源缺口：安置容量、无障碍位、运力、可达性缺口的差额；
   - 新调度方案：该档下重算得到的车辆—安置点安排、已安排与未安排人数。
4. 横向对比三档，指出哪一档开始出现明显缺口、哪一档现有资源无法覆盖。
5. 标出方案失效（出现不可达网格或大面积未安排）的档位，并说明需要新增什么资源。
6. 在结论中逐条标注这是在同一演练快照上的 what-if 计算，不是天气预报，
   也不代表真实雨情会按该档位发生。
7. 结束前附带下一步动作按钮（生成调度方案、生成转移任务、生成应急决策报告）。

## 输出要求

- 三档结果以统一表格或统一字段顺序并列，便于逐项对比；
  每档都必须同时给出风险、受影响人口、脆弱人口、资源缺口、调度方案五项。
- 数字口径一致：受影响人口、脆弱人口均以同一人口基数统计。
- 缺口必须与调度结果一起看：不能只报风险升高而不报未安排人数。
- 明确写出「相同输入快照、仅雨量为变量」这一前提。
- 明确声明：情景是演练设定下的假设推演（what-if），不是预报，不构成对未来雨情的预测。
- 若某一档触发了重算阈值讨论，说明阈值与冷却期的存在，以及需要人工确认后才重算。

## 禁止与边界

- **不得把情景称为预测、预报、趋势判断或概率情景。**
- 不得输出某档雨情下的积水深度、淹没范围或受灾损失金额。
- 不得混用不同快照的计算结果做对比，也不得只推演有利档位而隐去不利档位。
- 不得声称资源缺口已被方案自动解决；缺口应如实保留。
- 不得把 80/120/160 mm 描述为官方预警阈值或气象标准档位，它们是本演示的情景设定值。
- 不得省略「演练用途、结果需人工确认」的边界声明。
