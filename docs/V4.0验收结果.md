# V4.0 验收结果

日期：2026-10-05。使用合成演练数据；程序验收、浏览器验证与真人现场测试分别记录。

## 已完成

- 指挥台分为需求录入、任务执行、任务记录；现场端分为执行任务、补报情况。每页显示简短流程，手机优先显示本车当前步骤。
- 默认新建为真正的 0 人空白任务，示例 15 人须主动选择；升级不会删除浏览器已有任务。
- 名单预览可以直接改数量和地点，保留原值与修订；待核实补报不提前计入有效需求，缺项集中补齐，未知值不冒充零。
- 发布前可配置车辆、起点、容量与接收点资源；延续当前瑞安演示片区。
- 逐车接令、批量登记已联系人员、本车独立发车；到达后人工核验。空车下一趟从实际登记位置继续，保留先前送达记录与接收占用。
- 结束整场任务后只读留档；新建、切换情景、重置及导入另一场先归档。可明确结转尚未上车需求，历史达到限制时要求人工备份后选择清理。
- 守护助手默认读取主台同一场人数、路线和进度；独立算法沙盘明确隔离。建议发布只能打开主台核对框，不能代替人提交。
- 同 Wi-Fi 房间提供共享状态与实时事件；加入认证、版本冲突及独立存档已实现。GitHub 页面仍按浏览器独立保存。

## 验证证据

1. 主项目 **533/533 项**自动回归通过，覆盖业务状态、名单核对、逐车执行、多趟容量守恒、结束归档、两客户端房间联动、离线缓存与发布构建；测试命令为 `node --test tests/*.test.cjs tests/*.test.mjs`。
2. 独立守护沙盘实际测试集为 **78 项**（现有资产版本），`node tests/guardian/run-tests.mjs` 全部通过；没有把最初材料里的 82 项当作本版本实测数。
3. 浏览器实测：空白 0 → 示例预览 6 改为 20 → 保存后精确 20；发布、只让 1 号车接令/勾选本车已联系人/发车，上车并到达 5 人；指挥端地图、人数实时变化，核验后 5 人已完成、15 人仍待接。
4. 浏览器实测：第一趟后准备下一趟保留已核验 5 人；提前结束后原记录保留，新建空白任务为 0；配置车辆容量后实际上传 CSV，预览与保存均为 6 人，再次发布成功。
5. 浏览器实测：守护面板读取与主台相同人数和版本；计算新草案后返回主台确认，未点击发布时不产生发布事实。API 入口可见，默认显示未连接大模型。
6. 390 px 手机视口检查：现场任务选择、当前一步、主要按钮在紧凑布局中可见；这是浏览器响应式验证，不是真机麦克风测试。
7. 固定输入评估覆盖 20 人导入、待核实新增 3 人、采纳后 23 人，以及完整多趟与接收容量不足情景。逐趟输入、守恒检查和源代码哈希见 `dist/assets/evaluation.json` 与《V4.0可复现评估》。不能将算法比较解释为大模型效果或真实救援收益。
8. 更新页校验目标构建完整缓存与接管状态；旧缓存的就绪消息不能冒充新版本下载完成。更新保留任务与草稿。

## 仍需在实际环境完成

- 同 Wi-Fi 的手机真机加入、现场网络连通和麦克风实测。程序已验证两个独立客户端，不等于已在用户手机上验收；HTTP 手机页可能须使用键盘语音听写。
- 真实天气与大模型调用、服务器代理、GPS、真实通知渠道、公网共享服务未接通。
- 地图是有限瑞安道路片区；资源、速度、容量和人员为合成业务数据。多趟是逐趟重新计算，不保证全局最优，不自动拆分既定接送组，不等于真实安全导航。
- PPT 和讲稿为可编辑初稿；正式录屏、真人上手计时、团队信息、本人签字及组委会确认事项由团队继续完成。

## API 位置

面板顶部“自己接入 API”展示说明；配置文件为 `dist/guardian/agent/api-config.js`。该文件配置独立沙盘的模型路径，主台助手目前使用本地工具。推荐后续增加后端转发端点，密钥仅放 `.env`；公开网页只填写端点地址，不填写真实密钥。本轮尚未实现转发端点。
