# V4.1 车辆与工作人员资源库

这版把资源登记、约束计算和逐车执行连起来。主导航保持“需求录入 → 任务执行 → 任务记录”；指挥台标题右侧使用“资源录入 / 管理”，不用再增加一个工作页面。

## 怎么操作

1. 新建尚未发布的任务，打开“资源录入 / 管理”。先登记工作人员编号、角色与到岗状态，再填车辆型号、人数和位置，并选择司机与随车协助员。没有实际清单时，点击“填入演练示例”可获得可编辑的演练草稿。
2. 车辆总核载填写**当前座椅/轮椅布局下所有车内人员总数**，包含司机、随车工作人员及被转移人员。另填核定轮椅位数量。系统实时计算可接人数；例如总核载 8 人、司机 1 人、随车协助员 1 人，可接 6 人，其中轮椅乘客也计入这 6 人。
3. “建议编组”只填草稿，保留已填编组，不会把机动人员当司机，也不会自动保存。核对后点击底部保存，草案按本场资源重新计算。
4. 录入接送需求，到“任务执行”直接看逐车卡：车型、司机编号、随车员编号、接送人数、可接人数、需协助人数、轮椅人数/轮椅位。特殊需求有文字与色块共同标示。核对后发布。
5. 现场端选择车辆就能看到同一组编配和当前操作步骤。途中人员离岗或车辆故障，在指挥台“登记资源状态变化”中登记；关联车辆暂停推进，原发布记录、车上人员不会被重写。恢复后核对新草案并再次发布。

## 登记与调度规则

| 内容 | 当前实现 |
|---|---|
| 人员 | 最多 150 个编号；司机、随车协助、机动人员三类。无姓名、电话或证件字段。 |
| 车辆 | 最多 30 辆；类型、型号、总核载、轮椅位、当前位置、可调度状态及特别说明。 |
| 容量 | 从总核载扣除已编组工作人员；即使工作人员暂未到岗，也不自动把其座位改成乘客位。有效乘客容量最多 500 人。 |
| 轮椅 | 支持多轮椅位；轮椅人数不能超过核定轮椅位和接送人数。不会自动根据车型名称推定适配能力。 |
| 工作人员 | 同一编号不能重复编到多辆车；司机角色才能开车；需协助人员至少配一名到岗随车协助员，这是本演练设定，不是法规或实际资质核验。 |
| 未安排 | 缺司机、缺协助员、座位或轮椅位不足等条件会保留人数与原因，不显示成全部完成。 |
| 记录 | 路线保存当时的车辆与人员编配快照，报告和执行卡可核对；无真实通知发送。 |

## 兼容与边界

旧任务原“容量”表示可接乘客数，不能直接当总核载。打开旧资源时不会自动猜总人数或编入虚构工作人员，需要明确填入后保存。旧任务继续按原规则运行并标明人员未登记；更新不会改变已有任务记录。

发布后完整资源库只读，避免改动既有任务编配。此时允许登记车辆、工作人员和安置点的可用状态；更换司机、增减编组、改变车辆布局需在下一场任务中完成，本版未做执行中换人、换车。

新任务可继承已有车辆与工作人员登记；用户应重新核对到岗、位置、布局和容量。当前示例资源都是可编辑的演练值，不具备真实车辆资质、道路净高/宽度、涉水能力或医疗设备认证。车型与特别说明是人工核对信息；实际算法约束使用核定容量、轮椅位、人员角色与状态。

指挥台与现场端在 Pages 同浏览器标签页共享；同 Wi-Fi 跨设备仍需运行 LAN 服务。本版不新增模型、天气或公网共享服务。

## V4.1.1 录入入口优化

顶部可直接新增工作人员、车辆或填入演练示例；分类切换只更换显示内容，不会清空未保存的输入。新增后定位到新行，保存前漏填会定位到对应分类和字段；保存按钮固定在底部，并显示草稿未保存提示。人员批量粘贴提供独立入口。

已发布任务在资源窗口明确说明只读原因，并提供“登记状态变化”及“结束本场并登记下一场”按钮。后者先展示结束确认，再展示新建确认；不自动结束或创建，取消就停止。新建成功后直接打开可编辑资源录入，旧场记录保留。已结束的任务直接进入新建确认。
