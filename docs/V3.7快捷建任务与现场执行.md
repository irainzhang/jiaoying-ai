# V3.7：指挥批量建任务，现场快捷执行与补报

主线：**指挥录入名单或口述需求 → 集中核对 → 生成转移安排 → 人工确认发布 → 现场接收执行 → 发现变化时快捷补报 → 指挥核实与重算。**

指挥端可以直接发起任务，不必先去现场页逐条上报。现场页的主要职责是执行已发布安排，补报新增人员、道路变化和其他现场事实。

## 指挥端怎么用

1. 在“快捷建任务”输入或语音描述需求，也可“选择人员名单”读取 `.xlsx` / `.csv`。已有名单时可先下载当前演练的 CSV 模板。
2. 查看集中核对表：村庄、集合点、总人数、需协助人数、轮椅人数、同行关系。文字错误、未登记村庄或非法数值会显示原行号；有错误时不能提交整批。
3. 核实相似记录是否属于不同人员，再点击“确认这批需求并生成安排”。这一操作新增需求并生成草案，不会自动发布或替换正在执行的安排。
4. 到“安排转移”核对路线、车辆及未安排原因，人工确认模拟发布。执行端才会按已发布安排展示任务。

文字或语音示例：

> 演示村 A，在村委会集合点，新增六人，其中一人需要协助，轮椅零人，可以分组；演示村 B，在备用集合点，新增三人，无需协助，无轮椅需求，可以分组。

整理依据是本地规则。语音中的估计、范围、矛盾人数或未登记地点需先核对，不会靠猜测补齐。当前总量盘点、更正历史批次、累计已转移人数应走对应台账或执行流程，不能当作新增任务导入。

## 名单格式

| 列 | 填写方式 |
|---|---|
| 村庄 | 已登记村名或编号，例如“演示村 A”“VA”；支持明确的演示村别名 |
| 集合点 | 属于该村的已登记集合点名称或编号；未确定可留空待补 |
| 人数 | 每行新增人数，正整数；有“姓名”且该行人数为空时按 1 人整理 |
| 姓名 | 可选，逐人名单使用；只填写模拟姓名 |
| 需协助人数 | 总人数的子集；不确定留空，明确没有才填 0 |
| 轮椅人数 | 需协助人数的子集；不确定留空，明确没有才填 0 |
| 同行关系 | “可拆分”或“必须同行”；不确定留空待核实 |
| 备注 | 可选，保留与本批需求相关的说明 |

支持每人一行，也支持按村庄、集合点汇总的一批人数。没有姓名且人数为空的行不会自动按 1 人处理。姓名不是身份认证或去重依据；相似记录仍需人工核对。

- `.xlsx`：读取首个非空工作表，其他工作表不会自动合并；界面提示所读工作表。合并单元格不会自动向下补值。
- `.csv`：支持逗号或制表符分隔、带引号的逗号和换行；建议另存为 UTF-8 CSV。兼容读取的中文编码会提示核对。
- 原始文件在当前浏览器中读取，不上传到 GitHub；确认后的任务字段、原话及模拟姓名可进入演练记录。
- 文件不超过 5 MB。旧 `.xls`、加密文件、宏和公式名单暂不支持；先另存为不含公式的 `.xlsx`，或 UTF-8 CSV。读取 XLSX 需要支持解压功能的浏览器，不支持时可使用 CSV。
- 每次最多 100 条需求。整场演练仍受 **500 名有效人员、200 个有效接送组** 限制，包含已有人员和组；超限或任一行校验失败时整批不写入，不会截断名单或只导入前几行。

## 执行端怎么用

1. 在“当前任务”选择负责的车辆，接收指挥已发布的安排，按界面当前下一步快捷登记联系、上车和到达。到达后仍由指挥台人工核验。
2. 发现新人时，直接在“快速补报”入口说出一批人数，例如“这里又发现三人，其中一人需要协助”。位置可沿用当前车辆下一接送点，或沿用一次选定的村庄和集合点；也可在原话中说清位置。
3. 检查整理后的确认卡，一次确认整批补报，无需逐人填写。语音或文字均不会未经确认就发出补报。
4. 指挥台收到待核实记录。缺少集合点、协助人数、轮椅人数或同行关系时保留“待补”，不强行要求现场逐项点击，也不默认填零；补齐后才参加路线安排。

当前等待总量、更正旧批次及道路等其他情况继续保留。快速新增补报不覆盖历史记录或已上车人数。两端数据变化后，旧确认卡须重新整理核对，防止按过期任务提交。

## 同步、保存与版本

- GitHub Pages 最新静态版可直接演练：[指挥台](https://irainzhang.github.io/jiaoying-ai/?v=3.7#command) · [现场执行端](https://irainzhang.github.io/jiaoying-ai/?v=3.7#field)。同一浏览器、同一站点的两个标签页共享记录；不同设备、浏览器、隐私窗口不共享。
- 已提交记录自动保存；“更多资料 → 备份与恢复”可导出 JSON。公开版数据存放于当前浏览器，清理站点数据会删除本机记录。
- **本地批量建任务需要 V3.7 后端能力。** 仅刷新新版页面不能替换已运行的旧 Node 服务。若页面提示服务需更新，可先用最新 GitHub 版演示。
- 现有 8769 服务不会被自动停止或重置。默认启动器和默认存档路径保持原样；旧服务仍运行时，要在独立端口、独立存档启动本版本，或由使用者正常停止旧服务后再启动。
- 新后端可读取原有演练状态；请先导出备份。不要用“导入名单”代替“备份恢复”，两者分别表示追加需求与恢复整场演练。

## 已实现与后续边界

这一版实现了本地名单读取、批量规则整理、整批校验与原子提交、人工核对后生成安排、任务联动和现场快捷补报。新需求不会自动改写已发布方案，也不会改动已经上车人员的原车关系。

尚未接入 DeepSeek、大模型或 Agent；浏览器语音识别可能联网且取决于浏览器支持，不保存录音。真实彩云天气、跨设备共享后台、真实 GPS、多趟换车和真实业务名单权限仍未接入。原型用于合成演练，不表示真实灾情下的调度授权或安全导航。
