# V3.8 天气与运输联动设计

当前版本使用合成雨情演练。天气卡读取既有 `state.data.weather`，展示最近 1 小时累计雨量（mm）、演练等级、更新时间和来源；不代表官方预警，不预测积水深度。

## 本轮交付与边界

- 新增 `dist/weather-panel.js` 与 `dist/weather-panel.css`，采用经典脚本与 UMD 导出。纯视图模块不联网、不启动计时器、不写状态。
- `JiaoyingWeatherPanel.render(state, { btn, disabled })` 返回天气卡 HTML；`deriveWeather(state)` 提供展示数据。`btn` 可复用宿主按钮函数，`disabled` 用于阻止请求期间重复操作。
- 20、50、80 mm 按钮和“启动雨情演练”按钮输出 `data-ac="weather-demo"`，以 `data-rain` 传递模拟雨量；启动按钮默认 50 mm。宿主控制器负责调用 `action('weather', { rainfall })` 并处理版本冲突，天气卡自身不提交动作。
- 卡片优先展示宿主提供的演练等级；没有等级时，按小于 50、50 至不足 80、80 及以上 mm 分为 1、2、3 档。这是演练阈值，不是气象预警标准。
- 本轮已将 `rainfall`（0–300 的整数）接入本地与 Pages 的同一业务层，保留旧 `preset` 兼容。同级变化只更新雨情；等级变化触发草案复核，既有发布方案不被自动替换。
- 实时天气、天气定时获取与自动事件管线尚未接入；以下接口是下一步设计，不代表现有服务已实现。

## 天气接入预留结构

建议继续扩展既有 `weather` 对象，避免另起一份互不一致的状态。当前 `rainfall`、`unit: 'mm'`、`window`、`level`、`updatedAt`、`trigger` 字段保持兼容。

```js
weather: {
  sourceMode: 'simulation', // 将来可支持 observation / forecast；当前仅模拟
  rainfall: 50,
  unit: 'mm',
  window: '最近1小时累计',
  level: 2,                // 演练分级，不是官方预警
  updatedAt: '...',        // 本系统最近写入时间
  source: { provider: 'caiyun', stationOrGrid: '...', sourceUrl: '...' },
  observedAt: null,        // 数据观测时刻，与写入时间分开
  forecast: null           // 将来：issuedAt、validFrom、validTo、累计量、单位、范围
}
```

`source`、`observedAt`、`forecast` 当前只是预留元数据。天气卡不会据此宣称已联网。彩云当前降水强度 mm/h 不能直接赋给最近 1 小时累计量 mm；需要明确时间序列、采样间隔、缺测处理与累计窗口。预报累计量同样不能冒充实测累计量。

## 后续自动事件与运输协同

1. 后端定时获取天气，密钥从服务器 `.env` 读取；浏览器只读取已归一化的天气状态。轮询周期、时间窗和提供商额度由部署时配置，当前没有启动此服务。
2. 校验区域、时间、新鲜度、单位与异常值。过期或断流保留最后有效记录，明确“数据过期”；不能自动切换成模拟数据却继续标作实况。
3. 为每次天气观测生成事件 ID，保留来源和观测时间。相同记录幂等去重，小幅变化累计；跨演练阈值或持续恶化时产生“需复核运输安排”事件。
4. 事件携带当前 `session`、`revision`、`inputVersion`、`executionVersion`。只基于同一快照计算草案，沿用现有版本校验；新反馈到达后重新核对，不能覆盖较新任务。
5. 运输评估读取等待、已上车、已到达人员以及车辆、安置容量、已核实道路情况。保留已执行事实与未安排人员；天气恶化本身不等于道路封闭，封路应有现场反馈或可信道路事件。
6. 输出变化解释：哪些任务受影响、原路线与建议路线、资源缺口、需要核实的事项。建议只生成草案，由人查看后点击确认发布。
7. 发布继续使用人工点击闸门，不要求手输姓名或固定确认文字。未选填操作人时记录“演练值守”；真实点击、令牌绑定、过期校验和执行记录仍保留。Agent 和定时事件不能自行批准。

## 验收建议

模拟 20 → 50 → 80 mm，确认雨量、演练等级、时间与来源同步更新；小幅同级变化不冒充新官方预警。测试无数据、非法数值、mm/h 单位、过期观测、重复事件以及版本冲突。检查运输草案保留已上车人员、未安排清单和人工发布入口。接入真实天气后另做带真实服务的端到端验证，并单独记录断网、超时与限额时的界面表现。
