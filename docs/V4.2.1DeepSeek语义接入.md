# V4.2.1 DeepSeek 语义录入

2026-10-06。当前已接入本机后端语义代理，支持人员需求、现场新增补报、车辆、工作人员、安置接收点。它把原话转成待核对字段，不自动保存、派车、发布或更新执行状态。

## 从哪里使用

1. 在项目目录双击 `启动演示.cmd`。默认打开 `http://127.0.0.1:8769/#command`，以实际启动输出为准。已有任务和本机存档保留。
2. **人员需求**：指挥工作台 → 需求录入 → 语音 / 文字 → 输入或说出情况 → 整理需求。模型返回后，在原核对表修改地点、人数和分组条件，再保存。
3. **资源**：资源录入 / 管理 → 选择工作人员、车辆与编组或安置接收点 → 语音输入 → 整理并预览 → 补齐缺项 → 确认加入草稿 → 保存资源。可直接修改语音转写文字；Excel 仍使用本地模板解析。
4. **现场新增人员**：现场执行 → 补报情况。快捷新增补报和“新增待转移人数”表单共用该语义服务；核对后点击补报，指挥端收到待核实记录。
5. 页面显示“本机代理已配置”只表示配置完整；每轮预览显示“本次来源：DeepSeek 语义识别”才表示该轮已成功调用。在线失败会明确显示“本地规则整理（不是大模型结果）”，保留原话和失败来源。

同一 Wi-Fi 协作使用 `启动同WiFi协同.cmd` 输出的房间加入链接。手机与电脑均先加入同一房间，语义请求由电脑后端转发；需电脑保持运行并联网。手机 HTTP 页面可能不支持浏览器麦克风，可以用系统键盘语音听写。未开放公网，未改防火墙。

## 配置与数据去向

真实配置只放项目根目录 `.env`，它已被 `.gitignore` 排除。`.env.example` 保持空白模板。

```dotenv
JIAOYING_AI_BASE_URL=https://api.deepseek.com
JIAOYING_AI_MODEL=deepseek-flash
JIAOYING_AI_KEY=只在本机填写
```

后端从项目路径读取 `.env`，不依赖启动时所在目录；同名环境变量优先。修改后重启服务。不要在 `dist/guardian/agent/api-config.js` 或其他前端文件填写真实密钥。运行配置不通过状态接口返回，也不打入 Pages 包。

点击整理会发送本次文字，以及必要的地区/接人点候选或资源编号候选到所配置的服务；不会发送录音、Excel 原文件、完整任务历史或密钥给网页。工作人员使用编号。模型未说明的协助人数、轮椅数、车辆型号或到岗状态留待补充，不能从车型猜运力，也不会生成经纬度。

浏览器语音识别负责“声音转文字”，DeepSeek 负责“理解文字并提取字段”；两者是不同环节。未使用现场真人音频验收，语音服务是否可用仍取决于浏览器与网络。

## 当前范围

- 新增 `GET /api/v3/semantic/status` 与 `POST /api/v3/semantic`，同源调用，沿用本机或已授权局域网房间访问控制。
- 输入只接受 `requestId / kind / utterance / context`；输出限定字段、人数类型、枚举、原话依据和提醒，不接收工具调用或业务动作。
- 明确区分新增、当前总量、更正及其他意图。总量不能当新增；多批现场补报不能只取第一批提交。
- Excel 解析、下拉填表、人数/位置校验、路线计算和发布仍沿用原模块。语义解析期间切换方式、改原话、关闭资源窗口或换任务会撤回旧请求；依据已更新的结果不会覆盖新输入。
- 原“AI 对话”、守护 Agent 工具编排、执行进展反馈、总量盘点及历史更正没有改成模型自主处理，仍使用现有规则和专用表单。彩云天气、GPS 及公网同步未接入。
- GitHub Pages 仍是静态离线演练。它不会调用你电脑上的密钥；若要供公网访客使用模型，需要另外部署带鉴权的 HTTPS 后端。
