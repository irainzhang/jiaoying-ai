# V3.5 数据来源与参赛准备

核对日期：2026-09-23。本文件对应公开原型的材料准备，不代表最终参赛材料齐备。AI、大模型及 Agent 本轮不接入；彩云天气继续保留契约，不调用实况服务。

## 1. 当前对外表述

建议定位为“面向基层防汛工作人员的人员转移协同原型”。它延续叫应的责任联系、组织转移和落实反馈场景，把现场文字或浏览器语音结果整理成可核实需求，再由调度工具计算建议、由人确认执行。

本队目前只有原“叫应”的公开报道，没有原系统源码、接口或官方合作授权。因此，只介绍本项目独立实现及公开可验证的改进，不断言原系统没有某项能力，不把原项目成效归入本队。

当前信息整理使用本地规则；路径和资源分配使用可检查的算法。模型入口与工具协议已预留，但没有实际模型调用。录屏、PPT、网页和答辩应一致使用这一口径。

价值可关联 [SDG 11.5](https://sdgs.un.org/goals/goal11) 和 [SDG 13.1](https://sdgs.un.org/goals/goal13)。本项目的覆盖人数、协助需求等待和未决事项是产品过程指标，不能直接替代联合国官方灾害损失指标，也没有验证减少伤亡的因果效果。

## 2. 数据目录怎样使用

机器可读目录在 `dist/evidence-library.js`，网页使用同一份数据，避免单独维护相互矛盾的来源表。

| 目录 | 公开获取方式 / 文件 | 真实与模拟的边界 |
| --- | --- | --- |
| OSM 道路与地理要素 | `dist/assets/maps/query.overpassql` 为查询；`ruian-osm-raw.json` 保存响应；`source-metadata.json` 保存时间和范围 | 道路几何为公开快照；不是灾时可通行证明，也不是行政区边界 |
| 道路计算图 | `dist/assets/maps/ruian-routing.json` 及对应构建脚本 | 道路来源可追溯；通行分钟数、演练封闭状态和业务用途是设定 |
| 人员和资源情景 | `exercise.cjs`、情景目录、`geo-scenario.cjs`；场景加载后可导出 JSON | 没有真实居民台账；人数、车辆能力、接收容量及点位用途均为演练 |
| 规则和计算工具 | `exercise.cjs`、`resilience.cjs`、`dispatch-large.cjs`、前端规则整理文件及测试 | 基线为声明式模拟规则，不是实际人工指挥效率；当前没有模型效果 |
| 现场输入 | 使用公开合成例句，浏览器语音或键盘输入后人工确认 | 应用不录制、存储音频；浏览器可能使用在线识别；确认后的文字会进入演练记录 |
| 天气 | `integrations.mjs` 的契约、演练天气状态 | 本版本不调用彩云实况；累计雨量和降水强度分开显示 |
| 流程依据 | 下列两份政府公开文件 | 只支撑流程解释，不为具体道路或接收点背书 |

OSM 数据基准为 2026-09-22T08:45:51Z，获取时间为 2026-09-22T12:50:33Z。按 [OSM 许可说明](https://www.openstreetmap.org/copyright)，数据使用 ODbL；保留署名、许可和派生数据库适用的同许可义务。原始提取和派生图的许可不自动决定独立应用代码的许可。当前仓库尚未单列应用及合成样例的再分发许可证，团队应在正式发布材料中说明。

比赛手册 PDF 第3—5页要求公开数据资源、列明公开获取方式，并要求已审核的地图来源。**公开 OSM 许可并不能证明满足该赛事地图审核条件；合成情景的参赛使用方式也仍需向组委会确认。** 本版本仅记录这两项待确认事项，不虚构审批结果。

公开网页和仓库不放入会议逐字稿、签名承诺书、证件号码、真实人员联系方式或现场录音。临时下载的预案和核对截图位于被忽略的 `tmp/policies/`，不随网页发布。

## 4. 8分45秒讲解脚本

下表是录制脚本和镜头安排，不是已制作的 PPT 或视频。演示数值必须由最终冻结版本生成；若某个情景结果没有改善，解释约束和失败原因，不替换成预设的有利数字。录制前完整走一遍操作，网页按钮名称以冻结版本为准。

| 时间 | 画面与操作 | 建议口播 |
| --- | --- | --- |
| 00:00—00:45 | 项目标题＋简明流程 | “我们关注的是基层叫应之后的落实：哪些对象还未联系、哪些人需要接送协助、道路变化后怎么安排、是否真正完成核验。本原型把这些环节放进一份可追踪台账。” |
| 00:45—01:20 | SDG 11.5、13.1 与三类过程指标 | “对应目标是灾害影响防范与韧性建设。我们检查需求是否被覆盖、需协助对象是否进入安排、未解决事项是否持续跟进。这些是演练过程证据，尚不代表实际减灾成效。” |
| 01:20—02:00 | 数据目录与架构图 | “底图和道路来自公开 OSM 快照；人员、车辆、接收容量及天气是合成演练。公开预案提供流程参考。当前版本用浏览器语音、规则整理和算法计算，尚未接入大模型或 Agent。” |
| 02:00—03:15 | 加载场景；同浏览器打开现场端与指挥台 | “现场上报新增12人，其中3人需协助，含1名轮椅人员。先核对新增还是当前总量，再核对地点、分组和原话。提交后指挥台出现待核实记录，核实后才进入需求台账。” |
| 03:15—04:30 | 方案与同快照基线逐车对比 | “两套方案使用相同人员、道路和资源条件。我们同时看覆盖、等待、接收点占用和未安排原因。资源不足时明确暴露缺口，不只展示更短的时间。” |
| 04:30—05:45 | 触发道路封闭或资源失效；看变更摘要 | “发生新的障碍后，旧方案不会静默替换。新草案列出受影响对象和资源约束，已上车对象保留约束。没有可行安排时，需要人工核实资源或组织增援。” |
| 05:45—06:45 | 人工确认；现场快速反馈；核验 | “指挥人员确认后才执行。收到信息、已联系、已上车、已到达和已核验是不同状态，普通反馈不会自动变成安全结案。” |
| 06:45—07:45 | 展开条款、来源与报告；导出 JSON | “每条流程依据都能回到文件、版本和页码。报告保留来源、方案版本、处理回执和未决事项。JSON 可保存这场演练，恢复时先校验，不自动补交草稿。” |
| 07:45—08:45 | 固定情景结果、现阶段边界、后续路线 | “当前验证的是这组公开演练条件下的程序与流程表现。接下来的模型理解能力需要独立对照；彩云实况和跨设备共享后端也尚未上线。我们会在真实业务核验和赛事数据来源确认后推进。” |

推荐 PPT 9页：问题与定位、SDGs、数据与边界、系统结构、现场上报、约束调度、失效应对、验证证据、推广条件。每页只保留一个关键问题，演示主线集中在第5—7页。模型接口示意必须标注“预留”，不要画成已产生真实调用的运行链。

## 5. 评估材料应如何呈现

- 固定公开情景至少覆盖：正常接送、道路中断、村级增员、车辆不足、接收点失效、恢复通行。结果来自当前求解器，记录版本、输入及耗时。
- 在相同输入和约束下比较规则基线与调度方案；并列覆盖人数、协助对象覆盖与等待、未安排原因、车辆和接收点分配、硬约束错误。
- 对不同覆盖人群不能只用平均时间宣布提速；未安排原因要区别通路、车辆座位、轮椅适配和接收容量。
- 把规则整理的表达测试单列；“不是新增20人，是现在一共20人”“两户”“5位老人”不应被错误累加或自动当作协助人数。
- 本轮没有 Agent 对照组，AI 准确率、模型耗时与独立增益应留空并标“未接入”，不可填零假装已经测试。
- 软件测试数量与业务效果分开。最终截图、测试数量、通过记录和公网版本须来自实际发布验证。

## 7. 前端读取约定

`window.JiaoyingEvidence`（浏览器）/ `require('./dist/evidence-library.js')`（Node）为纯数据对象，无网络请求、无模型调用。

- `sources[]`：`id/name/kind/publisher/url/access/jurisdiction/date/license/licenseUrl?/fields[]/use/limitations/assets[]/synthetic/contestApproval?`。
- `policies[]`：`id/title/publisher/date/version/jurisdiction/sourceId/status/section/page/url/summary/application/boundary/tags[]`。所有文本经过渲染层转义；外链使用安全打开方式。
- `limits[]`：`id/label/status/detail`。
- `submissionChecklist[]`：`id/label/status/detail/source`。
- `presentation[]`：`time/title/content`；`sdgs[]` 为公开目标链接；`noMatch` 为无匹配提示。

网页和报告可共同读这份目录。它是人工核读的小型静态证据库，按标签筛选不等于已接入检索 Agent。
