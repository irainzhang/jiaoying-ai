# V4.2 统一录入模块

资源库改为「手动新增 / Excel 导入 / 语音输入」。人员、车辆、安置接收点共用同一套导入和核对界面，不再要求粘贴逗号分隔文本。

## 操作

1. 在指挥台打开「资源录入 / 管理」。准备阶段可以编辑，已发布场次沿用既有只读规则。
2. 单条资源直接新增。批量登记时，在「Excel / 语音录入资源」选择资源种类，再下载该类 Excel 模板并填写、上传；每个文件读取首个非空工作表，多张表分别导出上传。
3. 也可切到语音输入，口述信息后结束识别，再整理预览。浏览器不支持语音时可编辑原话或改用表单、Excel。
4. 在预览里补齐缺项。地点和人员按当前场次提供候选，可搜索筛选；未知内容不会擅自猜成核载、可用状态或地图位置。
5. 点击「确认加入草稿」，核对车辆编组，最后点击「保存资源并重新计算」。导入不会直接发布任务；同批错误或重复编号不会半途写入。

Excel 模板为真实 `.xlsx`，兼容上传 `.csv` 文件；不支持旧 `.xls`、带公式、加密或带宏的文件。文件在当前浏览器读取，不上传到 GitHub。只登记工作人员编号，不要求姓名或联系方式。

## 为什么共用组件、分别配置业务

输入方式和交互流程共用，业务事实与保存动作保持各自明确的规则。例如司机候选按岗位筛选，车辆总核载必须扣除随车工作人员，安置点按接收人数核对；这些规则不能用一张通用无约束表替代。

| 修改目标 | 位置 |
| --- | --- |
| Excel / 语音切换、上传、模板、预览编辑、确认、提示、候选搜索 | `dist/entry-kit.js`、`dist/entry-kit.css` |
| 资源字段、表头别名、语音整理规则、各类候选和校验 | `dist/resource-intake.js` |
| Excel 文件底层读取及格式限制 | `dist/intake-file.js` |
| 浏览器语音识别生命周期 | `dist/voice-input.js` |
| 地点搜索下拉基础交互 | `dist/place-picker.js` |
| 资源草稿与最终登记衔接 | `dist/task-workbench.js` |
| 人员需求的业务解析与保存 | `dist/command-intake.js`、`dist/workspace-app.js` |

资源三类录入完整复用公共模块。需求录入复用方式选择、文件控件、Excel 模板和读取接口、地点选择入口。指挥台、现场补报、村级补报和助手等入口复用统一语音控件；各自保留需求核对、去重、版本检查和提交协议。接令、出发、到达、结束等状态动作继续用快捷按钮，不强加 Excel 上传。

## 后续嵌入其他业务

通过 `JiaoyingEntryKit.html()` 放置入口，再调用 `bind()`，配置 `getSchema`、`parseRows`、`parseSpeech`、`validate`、`onApply`。Schema 声明字段、候选、模板、示例；`onApply` 只接收经确认的草稿，实际保存由宿主负责。容器关闭时调用返回的销毁函数，中断识别并废弃尚未完成的读取；`hasPending()` 用来避免跳过预览直接保存。

语音目前使用浏览器识别和本地字段规则，未接入大模型理解。没说清的部分会要求补充，不代表自动完成现实核验。车辆类型或型号不会自动推断道路通行能力、资质或涉水能力。
