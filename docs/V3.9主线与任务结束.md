# V3.9 主线与任务结束

2026-10-05。主线：**录入需求 → 发布并执行 → 结束并留档**。

## 模块各负责什么

| 位置 | 负责内容 |
|---|---|
| 指挥台 → 需求录入 | Excel / CSV、文字与语音录入，核实现场补报，补充接人位置和协助信息 |
| 指挥台 → 任务执行 | 地图与模拟雨情、计算安排、点击发布、跟踪回执、核验到达、结束当前任务 |
| 指挥台 → 任务记录 | 当前记录、已结束任务、未完成事项、复盘与导出 |
| 现场端 → 执行任务 | 选择负责车辆，接收、联系、上车、到达；展示当前下一步 |
| 现场端 → 补报情况 | 整批补报新增人员、总数盘点、更正与异常；从二级入口查看处理记录 |

资源、资料、情景与设置放在二级入口。地图用于安排和执行；录入时按需展开定位，不再让每个页面承担所有内容。

## 每个模块怎么操作

页面顶部显示本页三步流程，常用操作优先出现，计算、原话、逐车路线和其他反馈按需展开。

| 模块 | 第 1 步 | 第 2 步 | 第 3 步 |
|---|---|---|---|
| 需求录入 | 上传 Excel / CSV，或语音、文字说明整批需求 | 核对人数、接人位置和协助信息；缺位置时展开地图定位 | 保存需求，进入任务执行查看安排 |
| 任务执行：尚未发布 | 看可安排人数、车辆与待协调人数 | 需要时展开逐车路线，核对具体接送安排 | 点击发布；打开现场端接收任务 |
| 任务执行：已经发布 | 查看当前下一步，落实已安排人员的联系 | 开始执行后跟踪上车与到达回执 | 点击“核验这批已到达人员”，一次确认已列出的到达回执；最后结束本场任务 |
| 现场端：执行任务 | 选择负责车辆 | 点击当前提示的接收、联系、上车或到达步骤，也可语音说明进展 | 核对整理结果后点击提交，指挥台同步更新 |
| 现场端：补报情况 | 一次说出或输入村庄、新增人数和协助需求 | 核对规则整理的整批结果；未知信息留待补 | 点击确认补报，在提交记录中看处理结果 |
| 任务记录 | 查看本场完成与未完成摘要 | 按需展开上报记录、历史任务或报告 | 导出保存；需要继续演示时开始新任务 |

语音只是输入方式，识别结果仍需点击提交。任务进展语音登记没有额外的“已经核对”勾选步骤（相似重复需求仍需明确核对，防止重复增员）；系统保留人数、位置、容量与版本检查。现场任务进展与异常补报分开，避免在同一区域出现两套相似表单。

模拟天气默认只显示一行摘要。需要演示降雨变化时展开，选择雨量后看复核提示；不用修改天气也能走完需求、发布与执行流程。规划默认显示摘要与发布按钮，逐车路线、重算和计算依据按需展开。

## 一次简单的演示路径

1. **进入指挥台**：首次已有 15 人演练底数，可以直接到「任务执行」；要演示导入，先在「需求录入」上传名单或填写示例，再核对保存。
2. **发布安排**：确认可安排人数、待协调人数与目的地，点击发布。容量不足的需求保持待协调。
3. **打开同浏览器现场端**：在「执行任务」选择车辆，跟随当前一步接收和联系。指挥台完成联系后点击开始执行，现场继续登记上车、到达。
4. **体验一次补报**：现场「补报情况」整批录入新增人数，提交后指挥台「需求录入」核实；需要改安排时，在「任务执行」核对新草案再发布。
5. **结束任务**：回到指挥台核验到达记录，点击顶部「结束当前任务」。只想结束当前演示、没有跑完全部人员时，选择页面提供的提前结束，未完成事项原样保留。
6. **查看记录**：导出本场结果。要再演示一轮，点击顶部「开始新任务」，旧场自动进入历史列表。

无需逐一使用所有功能才能结束一场演示；情景切换、资源调整、资料、详细算法比较都是辅助入口。

## 核实窗如何填写

上报人数作为事实展示，不再用不可编辑的普通输入框冒充可操作字段。可补充信息与上报事实分开；人数有误按更正流程留痕。未知协助、轮椅或分组信息保持未知，不自动当零；信息完整才生成接送组，暂不完整可先保存为待补需求。

## 怎么结束，结束之后会怎样

在指挥台「任务执行」点击 **结束当前任务**，查看已核验、待接、车上、到达待核验和未决事项摘要。无需输入指定确认文字。

- **完成任务**：只有全部有效人员已核验、没有待核实或待协调事项才允许使用。
- **提前结束**：可以结束未完成的整场演练；人员与上报仍保留原状态，报告不会写成全部解决。
- 结束后两端停止写入；旧窗口的执行、发布或补报也由业务层拒绝。
- **开始新任务**：先归档已结束的旧场，保留地图类型，恢复一套独立的 15 人演练底数。它不是空白名单，也不延续上一场运输。

历史最多 **10 场、合计 4 MB**。达到上限后拒绝新建，保留既有记录，不自动清除最早场次。导出 JSON 不会释放容量；本版尚无删除历史入口。

## 保存与恢复边界

当前结束状态保存在 `taskLifecycle`，与人员运输阶段分开；不会通过改阶段伪造已到达。旧数据没有该字段时按进行中读取。开始新任务将旧场完整快照平铺保存在 `taskArchives`，不递归嵌套历史。

恢复进行中的存档仍需重新核对发布；恢复已结束存档保持只读与原发布事实，不能用同场的旧进行中存档重新打开已结束任务。切换、恢复和新建均保留已有历史并检查上限。

公开版记录在当前浏览器保存，同浏览器两标签页同步，跨设备不共享。建议在「任务记录」导出需要保留的 JSON。

## 仍然没有接通的部分

雨量继续模拟，地图运输播放不是实时 GPS；真实天气、模型和后端转发未连接。主台文字整理使用规则，调度由算法计算；独立守护面板的发布不写入主台任务。

API 位置仍为 `dist/guardian/agent/api-config.js`，可从守护面板顶部 **自己接入 API** 查看说明。推荐以后由后端代理转发、真实密钥放服务器 `.env`；公开网页不填写或发布密钥。
