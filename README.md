# 叫应 AI · 瑞安防汛协同演练 V3.4

面向比赛评委和团队讨论的本地原型。沿用“叫应”的预警、联系、组织转移、反馈核验场景，在此基础上演示路径与车辆分配、人工确认、途中重规划。

**本地服务版与 GitHub Pages 浏览器分享版分开构建。首页底图为 OpenStreetMap 的瑞安市城区真实道路、水系与地名，已保存为本地矢量文件。业务人员、调度演练路网、风险、雨量和资源仍为合成演练数据。DeepSeek 大模型、彩云天气和真实定位均未接入。**

## V3.4.1：GitHub Pages 分享版

在线入口：[叫应 AI 演练与功能清单](https://irainzhang.github.io/jiaoying-ai/start.html)。源代码在 `main`，构建产物在 `gh-pages`；发布结果以部署状态与实际访问为准。

- 无需运行发布者的电脑；访客打开 HTTPS 链接即可体验两个网页，沿用同一套实际调度算法、村级台账与人工核实流程。
- 每位访客独立演练。同一浏览器、同一站点的标签页通过浏览器存储和通知联动；不同设备、浏览器配置或隐私窗口不共享状态。这不是多人联网指挥服务。
- 合成演练记录保存在浏览器 IndexedDB，事务完成后才确认提交，版本冲突需要重新核对。浏览器清理或存储限制可能导致记录丢失，重要记录仍请导出 JSON。
- 只输入演练数据。浏览器语音识别可能调用浏览器提供的在线服务，转写后仍需人工确认；没有接入 DeepSeek、彩云实况、真实定位或原“叫应”后台。
- 执行 `node scripts/build-pages.mjs` 得到 `tmp/pages-release` 和发布白名单 `tmp/pages-manifest.json`。不要直接把本地 `dist` 上传 Pages；公开适配只在构建产物加载，本地服务模式保持原样。

## V3.4：村级上报、确认卡与转移台账

- 现场网页默认进入“村级人数上报”，原车辆任务、快捷进展和异常反馈保留在“任务与异常反馈”。选择演示村、语音或文字描述，整理成可编辑确认卡，一次确认即可提交；疑似重复时额外要求明确声明属于另一批。
- 分开处理“新增一批”“当前待转移总数观测”“更正历史批次”。总数观测必须填写清点时间，只作对账，不自动累加。更正经审核后替换原批次，保留历史；已有上车/到达记录的批次禁止更改人数。
- 村级台账单列待核实新增、已核实待接、待补信息、车上、到达待核验、已核验。集合点、特殊需求或分组未知也能先上报；采纳后人数仍保留在总数与待协调清单中，补齐后才生成接送组。
- 轮椅人数包含在协助人数、协助人数包含在总人数。独立人员可形成最多 4 人的接送组；整组同行不拆分，容量不满足就列为待协调。最多 500 名有效人员 / 200 个有效组，单车仍为单趟。
- 不超过 8 个待接组时保留原候选搜索，更多组使用有界启发式插入；包含同快照规则基线候选，不宣称全局最优。没有改变已有车辆和真实地图的来源。
- 首次升级请双击 **`启动V3.4演示.cmd`**。本次保存了旧 8765 服务的升级快照 `tmp/before-v34-state.json`，启动器在存在该文件时恢复；后续操作仍仅存于服务内存，请导出保存。旧 8765 服务没有停止或重置，原执行进度保留。默认新版地址为 8767，启动器检查村级功能能力，避免错误复用旧后端。
- 实际口述需浏览器支持及麦克风；字段整理是本地规则，大模型未连接。演示村 A/B/C 与集合点均属合成目录，未虚构真实行政村或真实坐标。

114 项相关行为测试通过；双网页实测覆盖提交、核实回传、更正、补齐与总量观测。真实麦克风口述尚需在使用环境验证。

演示步骤与业务边界见 [V3.4村级上报演示说明.md](V3.4村级上报演示说明.md)。

- 浏览器语音识别 → 原话转写 → 本地规则整理 → 核对车辆/家庭/位置/人数 → 人工确认。可用文字走同一流程。没有连接云端大模型；未完成、否定、模糊、冲突或缺少位置/人数的表达会要求补充，不猜地点或默认人数。

- 验证包括 66 项相关行为测试，以及两个真实网页之间的发布、接单、联系、路障反馈/回执、上车与到达联动。麦克风录入与浏览器在线识别服务尚需在使用电脑上实际口述验证。

2026-09-23 已对照会议及后续确认整理 39 项需求：20 项在演练范围完成、17 项部分完成、1 项未完成、1 项按约定暂缓；这不是完成率。会后村级上报等新增要求单独列出。完整记录见项目根目录 `20260923会议功能完成与待办对照.md`。本轮保留现有演练状态，没有重置或更新公网版本。

首次升级双击 `启动V3.4演示.cmd`；之后可用 `启动演示.cmd`，会启动或复用隐藏的本机服务，并在默认浏览器打开两个网页：

- 指挥工作台：<http://127.0.0.1:8767/#command>
- 现场反馈：<http://127.0.0.1:8767/#field>

需要 Node.js 22 或更新版本。启动器优先使用系统 Node，也支持本电脑已有的 Codex Node 运行时。没有新增安装或防火墙设置。同一台电脑的两个网页共享服务内状态，通过 SSE 即时同步；不可用时约每 1.2 秒轮询一次。仅监听 `127.0.0.1`，不支持手机等另一设备直接连接。

刷新网页保留演练状态；服务重启会重置。重要记录请先导出 JSON。当前没有数据库或账号权限系统。V3 不能直接双击 `dist/index.html` 运行，也不能直接把 `dist` 上传 GitHub Pages 后获得两端同步。

## 本版范围

| 部分 | 实现 |
| --- | --- |
| 指挥工作台 | 首行真实地图与 AI 对话；中部天气、反馈与调度草案；底部通栏任务、资源和依据 |
| 现场网页 | 选择车辆与任务、快捷接单/联系/上车/到达、语音或文字整理、人工确认、异常反馈与处理回执 |
| 两端同步 | SSE 即时推送与轮询后备、版本冲突检查、请求编号去重；并发时先成功者生效，另一端须重新核对 |
| 路径与调度 | 开放路网最短路、车辆候选组合搜索、容量及轮椅位约束；最多 500 人 / 200 个有效组；小规模候选搜索、大规模启发式；单车单趟 |
| 途中重规划 | 已核实道路受阻、新增人员触发草案；从最近登记节点继续，已上车人员保持原车 |
| 稳定性 | 同演练等级雨量更新保留方案；跨级触发复核；所有新草案均需人工确认才替换 |
| 反馈闭环 | 待核实、采纳、不采纳、待协调、已处理；同路段障碍全部核实排除后才恢复开放 |
| 语音 | 浏览器语音输入；系统语音合成单条/自动播报与停止；识别期间暂停播报 |
| 决策报告 | 可阅读报告、浏览器打印/保存 PDF、完整演练 JSON 导出 |
| 后续接入 | Agent 契约、彩云 v2.6 查询模板与数据校验、位置来源标识；均不调用外部服务 |

聊天与语音后的字段整理当前为有限规则，不是已接入大模型。语音转写使用浏览器的实际识别服务；不保存录音，可能需要联网和麦克风授权。路径与调度算法实际计算，不使用固定答案。天气等级为演练触发参数，不是官方预警标准；雨量不会直接变成积水深度、道路封闭或新增受灾人数。

## 建议演示顺序（约 6 分钟）

1. 同时打开两个网页。指挥台初始 6 户 15 人，先观察同快照优化草案和规则基线。
2. 点击“核对并发布草案”，确认；在“任务进展”登记已联系全部家庭，开始模拟执行。
3. 登记 1 号车接到演练家庭 02，观察车上 3 人和最近登记位置。
4. 现场网页选择演练东桥，填写“演练东桥有倒树，车辆无法通行”，核对后提交。
5. 指挥台“核实并处理”。采纳后东桥变为封闭，受影响的旧路线暂停推进，生成新草案。核对原车人员保留、路线改变，再人工发布。
6. 现场新增 2 人，选择点位、协助需求，提交并核实。观察人数变化、余位校验、重新安排或待协调清单。新增家庭须联系后才能登记上车。
7. 点击小幅雨量变化，观察方案保留；点击演练等级升级，观察只生成复核草案。打开“播报这条”或自动播报。
8. 查看 Plan B、事件依据及决策报告。推进上车、到达、人工核验，或导出 JSON 留下输入与操作记录。

重置入口在“接口与范围”。重置会清除本场合成演练，影响两个网页。

## 基线与计算口径

模拟基线 `risk-nearest-feasible-3.0`：已上车人员先安排原车终点；待接家庭按风险降序、协助需求、编号排序，优先选择到安置点开放路网时间较短的可行安排，再比较到户时间、抵达时间和稳定编号。车辆首次确定安置点后保持，继续追加家庭。基线不是瑞安市实际调度制度或真实人工效果。

优化算法 `ruian-candidate-search-3.0`：每个车辆、家庭子集和安置点先保留局部候选，再比较车辆组合。依次优先保证可送达的车上人员、高风险人数、需协助人数、总覆盖人数，再比较风险加权接人等待、最后抵达和总行驶时间。风险 3 权重 3，其余需协助权重 2，其他权重 1；等待指标为各待接人员人数 ×（到户分钟 − 本车本轮出发登记分钟）× 权重之和（人·分），只计本轮剩余等待，车辆时间采用逐站登记值。这些为可调整演练规则，不声称已证明全局最优。

两者使用相同快照，均校验不拆户、座位、轮椅位、可达性、安置余位、已上车锁定和人数守恒。已到达占用计入安置容量；重复计算不重复扣减容量。无可行送达路径的车上人员留在原车待协调，不消失。单趟完成车辆不自动派第二趟。

初始情景优化可安排 15 人、规则基线 12 人；两者最后抵达分别为起点后 38 和 36 分钟。**覆盖对象不同，不能将时间差解释为同批人员提速，更不能作为真实防汛成效。**
